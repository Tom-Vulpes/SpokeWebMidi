SPOKE · Expansion port

The STEMMA QT port, wire by wire

SPOKE has a 4‑pin JST‑SH connector (STEMMA QT / Qwiic compatible). It carries ground, 5 V from USB, and two RP2040 GPIO pins, GP26 and GP27. Use them as an I2C bus for sensors and screens, or for audio, buttons and LED strips.

V+ 5 V (USB VBUS) SDA GP26 SCL GP27 Code busio.I2C(scl=board.GP27, sda=board.GP26)

Experimental: use at your own discretion

The STEMMA QT connector is an advanced, experimental feature. Anything you connect to it, and any code on this page, is used at your own discretion and risk. Check each device’s voltage and wiring before plugging it in; damage from connected hardware isn’t covered.

The red wire is 5 V, not 3.3 V

V+ on SPOKE’s connector comes straight from USB (VBUS). Any I2C device you plug in must accept 5 V power, or go through a 5 V → 3.3 V step‑down converter. Most Adafruit STEMMA QT boards have a regulator and are fine; many SparkFun Qwiic boards are 3.3 V only.

The data wires are different: GP26 and GP27 are 3.3 V pins and must never see 5 V. Never connect the red wire to either of them.

    Beyond I2C

    Other jobs for GP26 and GP27

    When nothing I2C is attached, the two signal wires are ordinary RP2040 GPIO with some extras: both are ADC inputs, they share one PWM slice (handy for stereo), and they sit next to each other (needed for rotaryio). Everything below is built into CircuitPython unless a library is named.

    Sound out

    A synth on the STEMMA port

    The RP2040 has no DAC, but CircuitPython can play audio as fast PWM on any pin. synthio turns SPOKE into a standalone polyphonic synth: every pad plays a note out of GP26 (the blue SDA wire) with no computer needed. Both synthio and audiopwmio are built into CircuitPython, so there’s nothing extra to download for the sound.

    The 1 kΩ + 10 nF low‑pass rolls off around 16 kHz and removes most PWM hiss. The 10 µF capacitor blocks the 1.65 V DC offset. Feed a powered speaker, a line input, or a small 5 V amp board such as a PAM8302, which can run from the red wire. Never wire a bare speaker straight to the pin.

    Good to know

    • Audio and I2C can’t share the port. GP26 is either SDA or an audio pin.
    • Stereo: GP26 and GP27 are channels A and B of PWM slice 5, which audiopwmio needs for stereo. Use PWMAudioOut(board.GP26, right_channel=board.GP27) and Synthesizer(channel_count=2).
    • Keep sample_rate at 22050 or lower; scanning 27 pads keeps the RP2040 busy.
    • USB‑MIDI still works alongside, so SPOKE can play sound and send notes to a DAW at once.
    code.py · 27‑pad synthio synth
    # SPOKE as a standalone synth: touch a pad, hear a note from GP26.
# Built-in modules only (synthio, audiopwmio). Needs neopixel.mpy in /lib.
import math
import array
import board
import touchio
import audiopwmio
import synthio
import neopixel

# Same note layout as the default SPOKE MIDI code (GP1 ... GP29)
midi_notes = [98, 96, 93, 91, 88, 86, 84, 81, 79, 76, 74, 72, 69, 67,
              64, 62, 60, 57, 55, 52, 50, 48, 45, 43, 40, 38, 36]

touch_pins = [getattr(board, "GP%d" % n) for n in range(1, 26)]
touch_pins += [board.GP28, board.VOLTAGE_MONITOR]   # GP29 is named VOLTAGE_MONITOR

# --- audio out on the blue (SDA) wire ---
audio = audiopwmio.PWMAudioOut(board.GP26)
# For stereo: audiopwmio.PWMAudioOut(board.GP26, right_channel=board.GP27)

# A soft sine wave sounds far nicer than the default square wave
SAMPLES = 256
sine = array.array("h", [int(math.sin(2 * math.pi * i / SAMPLES) * 20000)
                         for i in range(SAMPLES)])

envelope = synthio.Envelope(attack_time=0.02, decay_time=0.15,
                            release_time=0.5, attack_level=1.0,
                            sustain_level=0.7)

synth = synthio.Synthesizer(sample_rate=22050, waveform=sine,
                            envelope=envelope)
audio.play(synth)

pads = [touchio.TouchIn(p) for p in touch_pins]
pixels = neopixel.NeoPixel(board.GP0, len(pads), brightness=0.05)
pixels.fill((0, 0, 255))

held = [None] * len(pads)

while True:
    for i, pad in enumerate(pads):
        touched = pad.value
        if touched and held[i] is None:
            note = synthio.Note(synthio.midi_to_hz(midi_notes[i]))
            synth.press(note)
            held[i] = note
            pixels[i] = (255, 0, 255)
        elif not touched and held[i] is not None:
            synth.release(held[i])
            held[i] = None
            pixels[i] = (0, 0, 255)

    For a richer pad sound with detuned voices, vibrato and a filter, load the “synth” template in the SPOKE Code Playground.

    Experimental · Two boards

    Chain two SPOKEs together

    Connect two boards with a STEMMA QT cable and you get 54 pads on one USB connection. The second board runs as an I2C target using CircuitPython’s built‑in i2ctarget module and reports which of its pads are touched. The main board reads that and sends the notes over USB‑MIDI on channel 2, so you can route the extra pads to a different instrument.

    Load the second board first.

    Plug the second SPOKE into your computer on its own and save the “Second board” code below as its code.py. Unplug it.

    Load the main board.

    Save the “Main board” code as the main SPOKE’s code.py.

    Connect them and plug in only the main board.

    The red wire joins both boards’ USB 5 V, so the second board is powered through the cable. Never plug both into USB while the cable is connected. Unplug the cable before editing the second board’s code again.

    Why the bus is slow

    I2C needs pull‑up resistors, and neither SPOKE has them on GP26/GP27. The second board turns on the RP2040’s weak internal pull‑ups, which is enough at a gentle 10 kHz clock. That’s still about 100 reads a second, plenty for touch. If the main board can’t find the bus it waits and retries, so boot order doesn’t matter.

    Second board · code.py (I2C target at 0x42)
    # SECOND SPOKE: reports its 27 pads to the main board over I2C.
# Built-in modules only, plus neopixel.mpy in /lib.
import board
import touchio
import neopixel
from i2ctarget import I2CTarget

ADDRESS = 0x42

# Start the I2C target first: it switches on the internal pull-ups
# and lets the pads calibrate with the bus already live.
target = I2CTarget(board.GP27, board.GP26, (ADDRESS,))

touch_pins = [getattr(board, "GP%d" % n) for n in range(1, 26)]
touch_pins += [board.GP28, board.VOLTAGE_MONITOR]
pads = [touchio.TouchIn(p) for p in touch_pins]

# Powered through the cable, so keep the LEDs dim
pixels = neopixel.NeoPixel(board.GP0, len(pads), brightness=0.03)
pixels.fill((0, 255, 120))

state = bytearray(4)      # 27 pads packed into 32 bits
last_bits = 0

while True:
    bits = 0
    for i, pad in enumerate(pads):
        if pad.value:
            bits |= 1 << i

    if bits != last_bits:
        for i in range(len(pads)):
            on = bits & (1 << i)
            pixels[i] = (255, 0, 255) if on else (0, 255, 120)
        state[:] = bits.to_bytes(4, "little")
        last_bits = bits

    # Answer the main board if it is asking (timeout=-1 = check once)
    request = target.request(timeout=-1)
    if request:
        with request:
            if request.is_read:
                request.write(state)
            else:
                request.read()
    Main board · code.py (54 pads, two MIDI channels)
    # MAIN SPOKE: plays its own pads on MIDI channel 1 and the
# second SPOKE's pads on channel 2. Needs adafruit_midi and neopixel in /lib.
import time
import board
import busio
import touchio
import neopixel
import usb_midi
import adafruit_midi
from adafruit_midi.note_on import NoteOn
from adafruit_midi.note_off import NoteOff

SECOND = 0x42

# --- I2C first; wait until the second board's pull-ups appear ---
i2c = None
while i2c is None:
    try:
        i2c = busio.I2C(scl=board.GP27, sda=board.GP26, frequency=10_000)
    except RuntimeError:
        print("Waiting for the second SPOKE...")
        time.sleep(0.5)

midi_notes = [98, 96, 93, 91, 88, 86, 84, 81, 79, 76, 74, 72, 69, 67,
              64, 62, 60, 57, 55, 52, 50, 48, 45, 43, 40, 38, 36]

touch_pins = [getattr(board, "GP%d" % n) for n in range(1, 26)]
touch_pins += [board.GP28, board.VOLTAGE_MONITOR]
pads = [touchio.TouchIn(p) for p in touch_pins]

pixels = neopixel.NeoPixel(board.GP0, len(pads), brightness=0.03)
pixels.fill((0, 0, 255))

midi = adafruit_midi.MIDI(midi_out=usb_midi.ports[1], out_channel=0)

local_held = [False] * 27
remote_held = [False] * 27
buf = bytearray(4)


def read_second_board():
    """Return the second board's pads as a 27-bit number, or None."""
    while not i2c.try_lock():
        pass
    try:
        i2c.readfrom_into(SECOND, buf)
        return int.from_bytes(buf, "little")
    except OSError:
        return None          # not answering right now, try next loop
    finally:
        i2c.unlock()


while True:
    # --- this board: channel 1 ---
    for i, pad in enumerate(pads):
        touched = pad.value
        if touched and not local_held[i]:
            midi.send(NoteOn(midi_notes[i], 110))
            local_held[i] = True
            pixels[i] = (255, 0, 255)
        elif not touched and local_held[i]:
            midi.send(NoteOff(midi_notes[i], 0))
            local_held[i] = False
            pixels[i] = (0, 0, 255)

    # --- second board: channel 2 ---
    bits = read_second_board()
    if bits is not None:
        for i in range(27):
            touched = bool(bits & (1 << i))
            if touched and not remote_held[i]:
                midi.send(NoteOn(midi_notes[i], 110), channel=1)
                remote_held[i] = True
            elif not touched and remote_held[i]:
                midi.send(NoteOff(midi_notes[i], 0), channel=1)
                remote_held[i] = False

    time.sleep(0.005)

    To chain a third board, give it a different ADDRESS (e.g. 0x43) and read it the same way. Power gets tight quickly though, since every board runs from one USB port.

    Troubleshooting

    Why two touch pads stop working when I2C is on

    Plug in an I2C device and the pads on GP28 and GP29 (the last two in touch_pins) can read as permanently touched, flicker, or disappear. The cause is physical: those two pins are next‑door neighbours to SDA and SCL, and SPOKE’s touch sensing is sensitive enough to notice.

    Touch sensing is done in software, and calibrated once.

    The RP2040 has no touch hardware, so touchio charges each pad, lets go, and times how long it takes to drain through SPOKE’s 1 MΩ resistor. A finger slows the drain. At startup each pad sets threshold = reading × 1.05 + 100, so anything that adds about 5% afterwards looks like a finger. It’s the same reason the FAQ says to press Reset after clipping on fruit.

    GP26–GP29 are four consecutive pins on the chip.

    They’re pins 38, 39, 40 and 41 on the RP2040 package, the corner that holds all four ADC inputs, and their traces run side by side to the connector and pads. Every pair of neighbouring conductors has a little capacitance between them.

    Turning I2C on changes what the pads “see”.

    Before I2C, GP26 and GP27 float, so the coupling to them hardly counts. Once a breakout is attached its pull‑up resistors tie SDA and SCL firmly high, and the I2C controller drives them. That neighbouring capacitance now loads GP28 and GP29 for real, the drain takes longer, and the pad crosses its startup threshold without a finger. Clock edges during a reading add random kicks on top. In the default code, a pad that fails its startup check is skipped by the try/except, so it silently vanishes.

    See it on the drain curve

    Illustrative values for a ~12 pF pad on a 1 MΩ pull‑down. The dashed line is the trigger point calibrated at startup.

    Fixes, easiest first

    Start I2C before the touch pads.

    Create busio.I2C(...) first, then the TouchIn objects, so their startup reading already includes the I2C device.

    Recalibrate with a little more margin for GP28 and GP29 once everything is running (code below).
    Slow the bus and keep the cable short.

    Add frequency=100_000 to busio.I2C, and keep the STEMMA cable away from the GP28/GP29 pads.

    pad recalibration helper
    import time
import board
import busio
import touchio

# 1. I2C first, so the pads calibrate with it attached
i2c = busio.I2C(scl=board.GP27, sda=board.GP26, frequency=100_000)

touch_pins = [getattr(board, "GP%d" % n) for n in range(1, 26)]
touch_pins += [board.GP28, board.VOLTAGE_MONITOR]
pads = [touchio.TouchIn(p) for p in touch_pins]

# 2. Re-measure every pad and set a fresh threshold
def recalibrate(pads, margin=1.05, extra=100, samples=8):
    for i, pad in enumerate(pads):
        base = sum(pad.raw_value for _ in range(samples)) // samples
        if i >= 25:                 # GP28 and GP29 sit next to SDA/SCL
            pad.threshold = int(base * (margin + 0.05) + extra + 100)
        else:
            pad.threshold = int(base * margin + extra)

time.sleep(0.2)     # let the I2C device power up
recalibrate(pads)

# 3. Debug: watch the two neighbour pads while you poke the I2C device
for _ in range(20):
    print(pads[25].raw_value, pads[25].threshold,
          pads[26].raw_value, pads[26].threshold)
    time.sleep(0.1)

    How to tell which effect you’re seeing

    Print raw_value for GP28 and GP29 three ways: with no device plugged in, with the device plugged in but no I2C traffic, and while reading the device in a loop. If the number jumps as soon as the device is attached, it’s the extra load and recalibrating fixes it. If it only wanders while data is moving, it’s clock edges, and a slower bus or short cable helps most.
